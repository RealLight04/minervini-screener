# VCP 점수 모델 연결 설계안

**상태(2026-10-05): Stage 1과 Stage 2 적용 완료.** 실제 구현과 달라진 점은 `HANDOFF.md`의 2026-10-05 절이 기준이다.
달라진 점: 구 `vcp_events` 갱신은 끄지 않고 그대로 두었고(일지 화면에서만 빠짐), 백필은 60일이 아니라 40일(일봉 보존 한계),
RS 수집 실패일 방어와 백필의 입력 재계산(저장된 종가·RS가 8월~9월에 깨져 있어서)이 추가됐다. Stage 3은 아직 결정 전.

이 문서는 승인 전에 쓴 원안이다. 새 점수 모델(`app/vcp.py`)을 사이트 화면과 추적에 연결하는 계획이다.

## 1. 근거 (이미 끝난 검증)

- 시험 32개 통과(`tests/test_vcp.py`): 규칙 문서(글쓰기.txt)의 시험 6종, 책 사례(GRA), 깊이 왕복.
- 사람 라벨 검증(61개, 종목명과 점수를 가리고 "볼 만한가" 판정):
  - 점수가 "볼 만함"을 구분하는 AUC 0.78(90% 구간 0.65~0.89).
  - 60점 기준선의 재현율 97%, 정밀도 69%. A+, A, B 사이에는 차이 없음(각 75%).
  - 탐지가 읽은 수축과 피벗이 맞다고 본 비율 85%. 형성을 못 찾은 8개 중 볼 만한 것은 1개.
- 2010~2026 백테스트(5351건): 점수 등급이 높다고 수익이 낫지 않았다. 그래서 점수는 "모양 적합도"로만 표시한다.
- 한계: 라벨러 1명, 표본 61개, 생존편향 유니버스.

## 2. 현재 구조 (코드에서 확인한 것)

| 부분 | 지금 동작 |
|---|---|
| 판정 | `screen_stock`이 종가만 읽어 `detect_vcp`(조정 3번 이상)로 판정. 신호와 피벗이 여기서 나옴 |
| 레지스트리 | `update_vcp_registry`: 적격 = 추세 6조건 + 탐지 + 베이스 저점이 150일선 위. 돌파 = 종가 >= 피벗 이고 (거래량 1.4배 또는 3거래일 유지) |
| 신원 | `vcp_events`에 유니크 제약이 없고 리셋 시 `first_detected`가 바뀜. 같은 베이스가 중복 기록될 수 있음 |

## 3. 단계

Stage 1 (그림자 모드, 위험 낮음)
- 새 분석을 매일 계산해 저장하고 화면에 점수만 보여준다. 신호, 피벗, 매매 계획, 레지스트리, `vcp_events`는 그대로.

Stage 2 (추적 전환)
- 새 테이블 `vcp_formations`로 형성을 추적하고 VCP 일지를 새 테이블로 바꾼다. `vcp_events`는 읽기 전용으로 보존한다.

Stage 3 (이번에는 안 함)
- 신호, 피벗, 매매 계획을 새 피벗으로 교체. 피벗 타이밍은 백테스트에서 중립이었고 매수 안내에 직접 영향이라 따로 결정한다.

## 5. Stage 2 변경

새 테이블 `vcp_formations`
- 신원: `stock_id` + `key_date`(베이스 고점 날짜)에 유니크 제약. `first_detected`는 불변.
- 열: 상태, `base_seq`, 베이스 고저, 피벗, 수축 수와 깊이, 점수(처음, 최고, 최근), 항목별 점수 JSON, `trend_grace`,
  돌파 기록(`breakout_date`, `breakout_price`, `breakout_volume`, `avg_volume`, `volume_ratio`, 등급, 돌파 전날 점수),
  결과(`outcome`, `outcome_date`, `outcome_pct`), 돌파일 국면(`regime_at_breakout`, `pct_above_200_at_breakout`).

상태 전이 (`app/vcp.py`의 `evaluate_state` 그대로)
- 등록: 추세 6조건(`_trend_ok`) 통과 + 점수 60 이상 + 상태 WATCH 또는 NEAR_PIVOT(또는 돌파 3거래일 이내).
- 유지: 점수가 45 이상이면 유지(깜빡임 흡수. 기존 `VCP_QUALITY_HOLD`와 같은 값).
- 돌파: 종가가 피벗 위면 BREAKOUT. 거래량 조건 없음. 기존 "1.4배 또는 3일 유지" 규칙과 `breakout_watch` 상태 삭제.
- 실패: 돌파 뒤 종가가 피벗 아래면 FAILED_BREAKOUT. 같은 형성을 새 형성으로 다시 만들지 않고 첫 돌파 기록도 바꾸지 않음.
- 무효: 종가가 베이스 저점 아래, 추세 이탈이 grace(2일) 초과, 15일 이상 재확인 안 됨이면 INVALIDATED.
- 새 고점으로 베이스가 바뀌면(`key_date` 변경) 새 형성이 되고 `base_seq`가 1 늘어난다.
- 결과 추적은 `update_breakout_outcomes`와 같은 규칙(돌파일 종가 진입, 손절 8%, 목표 2.5R, 120일 timeout)을 새 테이블에 적용.

화면
- VCP 일지를 새 테이블 기준으로 교체. 기존 `vcp_events` 통계는 "이전 판정 기록 n건"으로 한 줄 요약만 유지(표본외 이력 보존).
- 일지 하단 각주: 백테스트 결과(성과 차이 없음)와 라벨 검증 결과를 함께 표기.

백필(선택, 기본은 함)
- `scripts/backfill_vcp_formations.py`: 최근 60거래일을 하루씩 재생해 `first_detected`와 최근 돌파 이력을 채움. 안 하면 일지의 "최근 돌파"가 빈 채로 시작한다.

## 6. 같이 고칠 오래된 문구

- `routes.py` `volume_verdict`: "마른 베이스에서 돌파 → 건강" 같은 판정과 예전 백테스트 주장.
- `stock.html`: "백테스트상 거래량 마름이 성과와 더 관련 있었음".
- 기준: 2010~2026 백테스트에서 거래량 마름과 돌파 거래량은 성과 차이를 못 만들었고, 사람 눈에는 모양 판단에 도움이 됨.

## 7. 시험

- 기존 `tests/test_vcp.py` 32개 유지.
- 신규: 상태 전이(메모리 SQLite), 신원 유지(같은 날 두 번 돌려도 행 불변), 돌파 기록 1회, FAILED_BREAKOUT 후 기록 보존.
- 스모크: 운영 DB를 복사한 사본에서 `force` 재스크리닝 후 건수와 분포를 오늘 값(형성 476, 60점 이상 117)과 비교.

## 8. 위험과 되돌리기

- Stage 1: 새 컬럼은 NULL 허용이고 예외를 격리하므로 신호가 달라지지 않는다. 되돌리기는 화면에서 숨기기만 하면 된다.
- Stage 2: `vcp_events`를 건드리지 않아 일지 라우트와 템플릿만 되돌리면 된다.
- 같은 날 재스크리닝을 두 번 하면 레지스트리가 오염되므로, 유니크 제약과 멱등 갱신으로 막는다.
- 공개 사이트에 즉시 반영되는 파일(템플릿)은 워크트리에서 확인한 뒤 옮긴다.
